# Безопасность и SSO

## Доверие

Владелец определяется единственным `Notify__OwnerSub`, проверенным по подписанному токену SSO. Email, имя и роль admin не подменяют sub. Токены интеграций и устройств — случайные 256-bit значения; в БД хранятся только SHA-256 хеши. Устройства действуют 30 дней, интеграции 90, веб-сессия 8 часов без sliding expiration. Изменение этих сроков — версия политики, не клиентский параметр.

БД привязывается к sub владельца. Смена `OwnerSub` не передаёт существующие устройства и данные другому аккаунту: сервер отказывается стартовать. Копирование тестовой БД с credentials в production не является процедурой регистрации владельца.

REST и MCP используют одну бизнес-логику. Интеграции не имеют права ответа. Повышенное решение содержит серверный nonce, устройство, запрос, хеш содержания, конкретный ответ и срок; проверяется подпись зарегистрированного P-256 ключа и одноразовость в транзакции с окончательным решением.

Нативная SQLite закреплена на 3.53.3; при старой версии до исправления WAL-reset сервер отказывается стартовать. Данные не заменяются фиктивной in-memory БД ради тестов.

Android создаёт ключ подписи в Keystore с `setUserAuthenticationParameters(0, BIOMETRIC_STRONG | DEVICE_CREDENTIAL)`. Обычный токен и история шифруются отдельным AES-GCM ключом Keystore, backup выключен. Подпись на сервере подтверждает владение зарегистрированным ключом; hardware attestation и защита от модифицированного/root-клиента не заявляются.

## Первичная привязка и восстановление

1. Android проходит Authorization Code + PKCE через системный браузер как public client. Секрета confidential client в APK нет.
2. Сервер проверяет RS256, issuer/JWKS, audience Android-клиента, срок, sub владельца и `token_use=access_token`. ID token вместо access token отклоняется.
3. Сервер сохраняет enrollment, ключ телефона и recovery-флаг; создаёт external step-up от confidential web-клиента с `reauth_password_mfa`.
4. В SSO пользователь вводит свежий пароль и TOTP либо пароль и Passkey. Секреты факторов не попадают в Notify.
5. В callback сервер проверяет state/iss, погашает code на SSO с client authentication и PKCE, валидирует подписанный proof: profile, audience, subject, action, payload hash, nonce, assurance, pwd+otp/hwk, transaction_id, security revision и срок.
6. Одноразово выпускается credential устройства. При recovery в той же транзакции отзываются все прежние устройства и их credentials. Токены интеграций сохраняются.

Enrollment ID — секрет получения результата, живёт 5 минут и хранится на телефоне зашифрованно. Credential выдаётся через него один раз. Нельзя вызывать восстановление только с JWT, заявляющим MFA: обязателен серверный redemption привязанного proof.

Если SSO недоступен или политика/факторы не позволяют требуемую проверку, новая привязка закрыта. Обхода через SSH-код, recovery code Notify или отключение проверки нет. Восстановление самого аккаунта SSO выполняется средствами SSO.

## Голосовые сообщения

WAV-файлы лежат в отдельном приватном `data/audio`; путь строится только из серверного id, поэтому нельзя передать произвольный путь или URL. Сервер проверяет реальный RIFF/WAVE-заголовок, PCM16LE mono 16 кГц, размер до 10 МиБ и длительность до 5 минут, а не только MIME. Незавершённые `.part`-загрузки и файлы без метаданных удаляются фоновой очисткой; квота диска ограничивает суммарный размер и при заполнении отклоняет новую загрузку.

Скачивание требует авторизации и владения: устройство владельца либо интеграция того источника, которому принадлежит файл. Повышенное голосовое уведомление требует отдельного action-bound подтверждения: сервер выдаёт точные bytes `alxprgs.notify.audio.v1`, телефон подписывает их после биометрии/PIN, а одноразовый grant на 60 секунд разрешает скачать только этот файл. Прослушивание не является согласием на выполнение задачи. FCM не содержит аудио.

Голосовые ответы Android становятся durable-командой агенту; при offline они ждут подключения до TTL, после чего истекают. Файлы и метаданные удаляются согласованно при TTL, удалении владельцем и очистке. Речевые модели и расшифровки не выполняются на общем сервере и не сохраняются Notify.

## Агенты

Регистрация агента — изменение управления, поэтому выполняется только после повышенного ответа доверенного телефона. Агент использует токен своего источника со scope `agents:connect`; отдельного скрытого входа нет. Один источник — один агент. Отзыв источника немедленно закрывает WebSocket и отменяет неподтверждённые команды.

Агент подключается исходящим WSS на 443; на компьютере агента не требуется входящий порт, публичный URL или самоподписанный TLS. Сервер проверяет Bearer, scope, регистрацию и `agentId` в hello. Кадры ограничены 64 KiB, неизвестный тип закрывает сессию. Долговечные команды имеют eventId и подтверждаются ack; повторная доставка возможна, поэтому среда агента дедуплицирует eventId. Голосовые данные и медиа звонков не сохраняются как команды.

Notify не исполняет произвольный текст как команду оболочки и не импортирует код из сети. Какие задачи выполнять, решает только среда агента; `text_tasks`, `voice_messages`, `realtime_audio` — заявленные возможности, а не универсальное разрешение.

## Живые звонки

Исходящий звонок начинает только доверенное устройство владельца; входящий — только зарегистрированный агент с `agents:connect`/`realtime_audio` и **согласованной** версией call-протокола. Агент объявляет `callProtocols` в hello; сервер выбирает только `alxprgs.notify.call.v2` и возвращает `hello_ack.callProtocol`. Старый/неизвестный агент без общей версии не получает ringing: `call_protocol_unsupported`; текстовые и голосовые команды при этом остаются доступны. Молчаливая несовместимость v1/v2 запрещена. Второй звонок получает `busy`. Elevated-звонок (в любом направлении) требует подписи точных bytes `alxprgs.notify.call.v2` после сильной биометрии либо системного PIN/пароля. Proof привязан к `deviceId`, `direction`, `action`, `sourceId`, `agentId`, `sessionId`, `callId`/`inviteId`, `securityLevel`, `nonce` и сроку; подмена агента, сессии, вызова, направления или действия, чужое устройство, повтор и истечение отклоняются. Без неё сервер не создаёт и не принимает elevated-вызов. Вход в звонок, прослушивание и голосовое «да» не дают разрешения на опасные действия — для каждого создаётся отдельное confirmation.

Входящий вызов доставляется всем доверенным устройствам как data-only FCM `{type:"call", call_id, call_state}` без имени, текста и аудио; приложение показывает системное incoming-уведомление и не открывает микрофон до явного принятия. Full-screen intent и тело уведомления несут только действие показа карточки. Принятие/отклонение требуют явного нажатия собственной кнопки уведомления с одноразовым токеном, привязанным к `callId` и действию; внешний Intent к экспортированной Activity с `accept`/`decline` без валидного токена понижается до показа карточки, неизвестное действие игнорируется. Первый accept закрепляет устройство, остальные получают `call_taken` и актуальное состояние; FCM `accepted/ended` снимает уведомление. Android background launch и full-screen intent подчиняются системным ограничениям; при недоступности FCM остаётся foreground-опрос `/calls/incoming`, а физическая проверка вынесена во внешний gate.

Медиа ретранслируется в памяти по TLS, без STT/TTS, транскодирования, E2EE, записей и расшифровок. Кадры v2 — 652 байта; проверяются длина, seq (строго +1 для отправленных кадров), timestamp и generation. Mute не расходует seq и не отправляет речь. Barge-in очищает очередь старого generation; запоздавшие кадры отбрасываются и сервером, и Android. Очередь каждого направления ограничена 2 секундами; при переполнении звонок завершается `degraded`, backlog не копится. Android дополнительно ограничивает локальную очередь и завершает звонок при ошибке/переполнении отправки. Завершение звонка не ждёт зависшего peer бесконечно: служебные отправки агенту/телефону имеют таймауты, медиа-сокеты закрываются/Abort в `finally`, а конкурентные end/disconnect/revoke/timeout идемпотентны. Отключение любой стороны останавливает микрофон/воспроизведение и завершает звонок; приложение не переподключает запись скрытно. История звонка содержит только метаданные, direction и reason; удаляется вместе с 30-дневной историей.

Android запускает foreground service только после явного принятия/начала звонка и разрешения микрофона, показывает ongoing CallStyle notification; permission на микрофон/Bluetooth запрашивается лишь для звонка. Отказ в разрешении не обходится: звонок не начинается. Телефон использует системный audio focus/route; динамик, mute и завершение доступны. Речевые модели работают у агента/провайдера, не на общем сервере.

## Веб-кабинет

OIDC confidential client, PKCE/state/nonce, host-only HttpOnly cookie, SameSite=Lax, Secure в HTTPS-профиле. POST требует анти-CSRF токен и точный Origin. Credential не хранится в localStorage/sessionStorage.

Управление источниками и устройствами создаёт отдельный elevated-запрос `_system`. Только подписанный ответ телефона выполняет изменение. Результат с новым токеном зашифрован Data Protection и выдаётся один раз только инициировавшей сессии. Потерянный ответ не восстанавливается повторной выдачей секрета: создайте новую интеграцию и отзовите прежнюю.

## Эксплуатация

Каталог data содержит БД и Data Protection keys; оба нужны для восстановления. На Linux доступ только сервисному UID 1654 и администратору. Не храните реальные данные на общем сетевом/синхронизируемом диске. Защита от чтения диска root-пользователем не заявляется.

FCM содержит только ID события, а для звонка — `call_id` и состояние без текста/аудио. Данные читаются с авторизованного API. HTTP разрешён только development loopback; Android debug дополнительно разрешает адрес эмулятора 10.0.2.2. Release не доверяет пользовательским CA и не отключает TLS.

Не логируются callback query, bearer, proof и приватные данные. nginx должен отключать access log на callback-путях. Proxy к Scalar или хранение токена в Scalar выключены; API Reference собирается локально.
