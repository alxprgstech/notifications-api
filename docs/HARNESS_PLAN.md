# DeepSeek Harness: завершение ALXPRGS Notify

Версия спецификации: Spec Freeze v1, контракт HTTP v1, продукт 0.5.0. Этот документ фиксирует план; фактические результаты ведутся в ACCEPTANCE.

## Точка продолжения

Репозитории: `notifications-api` (.NET/API/MCP/веб/SDK/skill) и `notifications-app` (Kotlin/Compose). Начни с их AGENTS.md, README и `docs/ACCEPTANCE.md`. Сохраняй изменения владельца. Прочитай реальный код и lock-файлы: не заменяй существующие SQLite, SSO, outbox и Keystore типовой архитектурой.

Сначала воспроизведи сборки и тесты текущего SHA. Проблемы инфраструктуры и внешней настройки отделяй от дефектов кода. Короткая точка входа сервера — `src/Notify.Server/Program.cs`; бизнес-правила — NotificationService; Android — MainActivity/Api/Vault. Не добавляй обходной вход, стандартный пароль, флаг успешной биометрии или тестовую подпись в production.

Цель: закончить личный сервис для одного владельца, нескольких его устройств и агентов. До 1 000 событий/сутки, один звонок одновременно. .NET 10, Android 11+, FCM, SQLite WAL, один серверный процесс. Redis/брокер/постоянные речевые модели на общем EC2 не добавлять. SSO и его репозиторий не изменять. DNS, production, реальная отправка и платные API не входят в автоматическое выполнение этого плана.

## Порядок исполнения

Каждый пункт заканчивается работающим сценарием и проверкой, затем переходи к следующему. Новые capabilities включай только после серверной и клиентской реализации.

### H1. Завершить внешнюю приёмку основы

- Используй готовые настройки OIDC/step-up/FCM/App Links из OPERATIONS. Если владелец их ещё не предоставил, продолжай независимую разработку на локальном HTTP-стенде и явно оставляй внешний gate незакрытым.
- Проверь на настоящем Android обычный и elevated ответ, биометрию и системный PIN, две конкурирующие трубки, отзыв устройства, восстановление SSO, background/Doze и повторную синхронизацию. Root/hardware attestation не считать поддержанными без отдельной реализации.
- Проверь current SSO с `reauth_password_mfa`, отрицательные issuer/audience/nonce/owner/action/hash/replay. Локальный стенд доказывает RP-проверку, а не фактическую настройку production SSO.
- Дополни ошибки интерфейса, lifecycle/cancellation, восстановление после process death и поведение повреждённого/инвалидированного Keystore. Нельзя молча переключать elevated в standard.

### H2. Расширить контракты без поломки v1

- Сохрани message/confirmation и существующие форматы Answer/Challenge. Новые kind и новые структуры ответов вводи добавлением, с отдельным discriminator и обновлением SDK/MCP/Android/OpenAPI в одном этапе. Старому клиенту неизвестный тип показывай как «обновите приложение», без возможности ответить неподходящим способом.
- Добавь capability negotiation и минимальную версию клиента для новых типов. Не превращай незнакомый тип в обычное подтверждение.
- Обобщи action-bound challenge для ответов форм и действий звонка, сохранив v1 bytes/signature-профиль. Сервер по-прежнему выдаёт точные подписываемые bytes; клиент не канонизирует JSON самостоятельно.

### H3. Формы

- Форма содержит 1–20 полей с постоянными уникальными id, label, optional description и required. Типы: text, boolean, single_choice, multi_choice, number. Условия/ветвления, HTML, исполняемый JS и загрузки файлов не добавлять.
- Text: maxLength до 4 000; number: конечное число, optional min/max; choice: 1–20 уникальных вариантов с id и label; multi_choice без дублей. Настройки проверяет сервер при создании, значения — при ответе. Запрещай неизвестные поля/option id и неподходящие типы; не приводить строку к boolean/number молча.
- Android строит нативную Compose-форму, хранит черновик только локально, показывает ошибки рядом с полем. Отправка онлайн. Для elevated подписывается весь выбранный набор ответов. Один окончательный ответ, TTL, отмена и webhook действуют как у confirmation.
- Добавь REST, SDK sync/async, MCP `request_form`, документацию и тесты неверных/параллельных/просроченных ответов.

### H4. Подключение агентов

- Добавь зарегистрированный agent endpoint как сущность принадлежащего владельцу источника. Scoped credential `agents:connect`; соединение агент инициирует сам наружу к `/api/v1/agents/connect` по WebSocket/TLS, без открытого порта на ПК агента.
- Версионированное приветствие: agentId, name, capabilities, список доступных рабочих session/task id и коротких названий. Возможности: text_tasks, voice_messages, realtime_audio. Никаких команд оболочки из произвольного входного текста на сервере Notify.
- Heartbeat каждые 30 секунд, отсутствие 90 секунд означает offline. Управляющие события имеют eventId, protocolVersion, тип, correlation/session id. Сохраняемые команды подтверждаются ack и дедуплицируются. Аудиопоток не складывается в durable outbox.
- SDK предоставляет connector и интерфейсы AgentRuntime, Transcriber, Synthesizer. Конкретная среда агента выполняет задачи и обеспечивает контекст; Notify не умеет автоматически возобновлять любую чужую среду через один MCP. Поставь reference adapter с явно передаваемым Python callback, без автоматического импорта/исполнения кода из сети.

### H5. Голосовые сообщения

- Двусторонние сообщения Android ↔ agent. Для первого варианта хранения использовать WAV, PCM16LE, mono 16 kHz; ограничить файл 10 MiB и длительность 5 минут, проверять реальный WAV header/параметры/размер, а не только MIME. Отправитель может преобразовать иной формат до загрузки.
- Данные — приватные файлы отдельного data/audio, метаданные и связь с уведомлением — SQLite. Загрузка двухфазная: bounded temporary upload, проверка, atomic rename, транзакция метаданных/outbox; удалять брошенные uploads. Нельзя произвольно задавать filesystem path или remote URL.
- Глобальная дисковая квота аудио по умолчанию 512 MiB, configurable оператором; при заполнении отклонять новую загрузку с понятной ошибкой, не удалять свежие сообщения молча. Срок до 30 дней, более раннее удаление владельцем/истечение TTL очищает файл и метаданные согласованно.
- Агент offline: сообщение ждёт подключения до TTL. Показать состояния queued/delivered/expired/failed. Получение файла требует авторизации и владения; FCM содержит только id.
- Для elevated сообщения чтение/передача чувствительного содержимого проходит отдельное action-bound подтверждение. Не считать воспроизведение разрешением выполнить задачу.

### H6. Живой звонок

- Интернет-звонки в обе стороны внутри Android, без SMS/PSTN. Можно выбрать текущую задачу/сессию агента либо новый разговор. Агент должен иметь realtime_audio; иначе UI явно сообщает, что звонки не поддержаны.
- Первый транспорт — две исходящие WebSocket/TLS-сессии к Notify (телефон/агент), бинарное relay без серверного STT/TTS/транскодирования. Это упрощает NAT и обходится без TURN. Не называй соединение E2EE: сервер ретранслирует аудио в памяти, защита канала — TLS.
- Аудио PCM16LE mono 16 kHz, кадр 20 ms (640 bytes); бинарный заголовок seq:uint32 + timestampMs:uint32, network byte order. Допустим только согласованный формат. Очередь каждого направления не больше 2 секунд; при отставании не накапливать неограниченный backlog, завершать деградировавшую сессию с понятной причиной.
- Жизненный цикл: ringing → connecting → active → ended; отдельные причины rejected, missed, timeout, disconnected, unsupported. Ожидание ответа 45 секунд, максимум разговора 30 минут, одновременно один звонок владельца. Параллельный вызов получает busy. Лимиты — операторская конфигурация, расширение требует замеров.
- При offline-агенте звонок сразу недоступен. Самопроизвольного запуска процесса агента нет. При разрыве active-соединения остановить микрофон/воспроизведение и завершить звонок; не переподключать запись незаметно.
- Barge-in: agent-side VAD/речь пользователя посылает событие interruption с generation id; агент отменяет текущий синтез/ответ, Android очищает проигрывание старого поколения. Речевая обработка находится у агента/его выбранного провайдера. Нет конфигурации — нет ложного «рабочего диалога».
- Elevated-звонок требует системную проверку перед соединением. Любое опасное действие внутри разговора создаёт отдельный confirmation с описанием; голосовая фраза «да» и вход в звонок не являются универсальным grant.
- Android: foreground service только во время звонка, видимое ongoing notification, системные audio focus/route, Bluetooth/гарнитура, mute, динамик, завершение. Разрешения микрофона и foreground-service типов запрашиваются только при включении звонков. Учитывай текущие правила Android для CallStyle/full-screen intents; отказ в разрешении не обходить.

### H7. Качество интерфейса, SDK и документации

- Сохранить системные светлую/тёмную темы, читаемость ALXPRGS и адаптивность. Кабинет управляет и показывает историю, ответы остаются в Android. Добавить историю звонков только с метаданными, без записей и полных расшифровок.
- Иконки остаются optional, изображения локально загружены и ограничены, системная малая Android-иконка неизменна. Функции недоступного агента выглядят недоступными, а не ломаются после нажатия.
- Согласованно обновить OpenAPI/Scalar, SDK, stdio/HTTP MCP и skill. Skill не должен обещать выполнение/возобновление, которого среда агента не поддерживает. Проверить wheel отдельно от исходников.
- Выпустить подписываемый release APK с внешним приватным signing key; не публиковать и не коммитить ключ. Debug APK не считать production-релизом.

### H8. Проверки и ресурсы

- Сохранить существующие проверки основы. Добавить forms validation/races, agent reconnect/dedup/expiry, файловые квоты/неполную загрузку/удаление, доступ к чужому аудио, call lifecycle/busy/permissions/disconnect/barge-in, невозможность использовать call grant для отдельного действия.
- Audio pipeline проверять с настоящими байтами WAV и реальными WebSocket-соединениями. Для STT/TTS/runtime — локальные HTTP-стенды по их реальному контракту; успешное эхо транспорта не считать успешным ИИ-диалогом.
- Нужна ручная приёмка физического Android: фон/Doze, экран блокировки, обе проверки личности, гарнитура, плохая сеть, процесс killed, отзыв устройства, разговор с реально подключённым агентом.
- Измерить контейнер без нагрузки и во время одного разговора/всплеска API. Выбирать минимальный устойчивый лимит с запасом; не переносить прежние замеры только текстового ядра на голос. Ограничить буферы, фоновые задачи и одновременные uploads. Все модели остаются вне общего t3.small.
- Записать команды/версии/результаты/непроверенные внешние зависимости в ACCEPTANCE. После изменения схемы проверить backup/restore и документировать rollback. Не ослаблять проверки ради PASS и не скрывать реальные failures через skip.

## Готовность

Этап завершён, когда все включённые capabilities работают через REST/MCP/SDK и Android, отрицательные сценарии закрыты, фактические ресурсы измерены, внешний сквозной путь проверен либо явно оставлен блокирующим gate владельца. При отсутствии доступа не заявляй общую приёмку. Предоставь конкретный список внешних настроек без запроса секретов в чат. Production и публикацию не выполнять автоматически.
